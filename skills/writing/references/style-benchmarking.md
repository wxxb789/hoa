# 学一个作者的文风（样本 → 量化 → 契约改动）

## When to Use

operator 指定了外部作者/博客，要求“学他的写法”“总结他的写作风格”“融进我的风格”时使用。
单篇稿子的改进不走这里，走 `references/blog.md`。

触发后的目标不是写读后感，是**产出能写进写作契约的差异条目**。

## 1. 选样本：只看他想学的那种文本

- **只看博客 / 公开长文，不看他的书或专栏合集**：书稿是编辑过的正式语体，
  博客才是那种随性、灵动的味道。书稿会把你带向“教科书感”。
- 一个作者要按**系列/年份分开采样**，不能只取最近三篇：同一个人在“机制解释”“论文笔记”“年度总结”
  里用的是三套语气，混在一起平均掉就看不出功夫。
- 8–12 篇/人起可以看清“动作”；**要用指标对照自己的稿子就上 30 篇/人**，8–12 篇的中位数不稳（同一位
  作者 10 篇→30 篇，段长 238→210、句均 36.5→43.5、数字密度 8.2→9.5）。至少要有一篇他写“自己”的
  （总结/随笔），那篇最能暴露人称与情绪浓度。

## 2. 取文：先拿 sitemap，再挑 URL

```bash
curl -s https://SITE/sitemap.xml | grep -o '<loc>[^<]*</loc>' | sed 's#</\?loc>##g' > urls.txt
```

- 静态站 sitemap 常有全量 URL；目录页可能是 JS 渲染的（`grep href` 抓不到），拿不到就用浏览器
  `querySelectorAll('a')` 把链接列出来。
- 抓正文用页面抽取工具（一批 5 条，字符上限 60000）；长文会被截断，截断不影响风格判断。
- 偶尔单篇返回 0 字符：`curl -sL` 抓 HTML，正则去 `<script>/<nav>`，取 `<article>` 内容，再剥标签。
- 把每篇存成 `evidence/<作者>-<slug>.md`，别塞进上下文——风格判断靠统计 + 少量精读。

## 3. 先量化，再评价

`python3 scripts/style_stats.py <evidence-dir> <作者>-` 出一张表；**同一脚本再跑一遍自己的目标稿**，
否则没有对照组，只能说“他写得好”。

看四个差：

| 维度 | 读法 |
|---|---|
| 段落均长 | 150 字以下只有在靠小标题 + 图分担负载时才行（手册型）；没有这两样时，160–260 才装得下一个完整论证（现象→原因→反例→判断）。单看段长会误判 |
| 句均长 + ≤15 字短句占比 | 决定“节奏是叙事还是说明” |
| 小标题数 | 10+ 偏结构化的机制解释；2–3 偏随笔判断 |
| 数字密度 / 人称密度 / 括号 / 问句 | 决定“证据型”还是“判断型”，以及语气有没有分叉 |

## 4. 再精读 4–6 篇，只抄“动作”，不抄句子

每篇取 开头 1,000 字、中段 900、结尾 600 就够。要提出来的是可执行动作，例如：

- 开头第一屏交代“本文分几步、读者要付多少注意力”；系列固定引言用引用块放在正文前。
- 术语首次出现给「中文（English、ABBR）」，之后只用缩写；括号挂事实，不做解释器。
- 判断前置（先给结论清单再论证），而不是段尾补一句“这说明……”。
- 一段承载一个完整论证；段间不写过渡句，靠事实转场。
- 自我限定（“我的思考是个体的、阶段性的”）用来换可信度，不当作免责声明。
- 结尾抬一层（判断或边界），不列清单、不复述。

每条都要附**原文引用 + 链接**存进 profile，否则下一轮会重新猜。

## 5. 产出：profile + 差异表 + 三个选项

`outputs/style-profile.md` 五块，缺一块就会被追问：

1. 样本与方法（几篇、哪些系列、脚本路径）。
2. 每个作者：可抄的 3–5 个动作（带引文）、他的短板、**哪些不要抄**。
3. 他们的共同点——真正让文章好看的那几条，通常与技巧无关（判断先行、不写过渡句、敢限定）。
4. 我们现在的对照表（用同一脚本量的自己的稿子）。
5. 三种融入方案：最小增补（改 3–4 条契约）/ 双体裁模板 / 只改语气，给出建议顺序。

最后留 2–3 个需要 operator 拍板的具体问题（段落上限、是否强制配图、人称），一行一个问题，
让 operator 能「1 六句 / 2 强制 / 3 允许」这样回答。

30 篇级别的分析会产出十个左右决策点，那时把它们排成一页清单：**每问四行——现状（带数字）/ 两家怎么做 /
选项 A·B·C / 我的建议**。operator 会用「1B 2C 3C」这样一行回完；把所有间题写在正文里、只给一个“你看怎么样”，
他会反过来问你要选项。

拍板前不动契约；拍板后一次落盘，并校对站点写作契约自己的计数口径（「两类/三类文章」「段落 3–5 句」
这类数字最容易只改了一处）。**结论要先补工具能力才能执行时，拆成两阶段**：先补能力（如站点生成器的图注/
外链），再写条款；否则契约会要求工具做不到的事，下一轮在执行时又得缩回来。

## 6. 坑

- **书 vs 博客**：书稿结构（小标题 10+、节节独立）套到“一次经历”上会立刻变回报告体。已经踩过一次。
- **抄结构不等于抄到好看**：他们的节奏来自十年选题与判断，抄骨架只得到外壳。profile 里要写明
  这一点，否则会被误以为改完契约就该变好。
- **情绪浓度不可跨体裁搬运**：人生随笔的腔调搬到“该不该给 agent 生产权限”这类技术决策上会变鸡汤
  技术文；反过来，机制解释的第三人称抽离会稀释亲身经历里的判断力。两类文本分开取样、分开用。
- **不要把两个作者的指标平均成一个中间值**。他们的差别（段长 114 vs 210、人称 3.0 vs 5.4）本身就是
  选题信号：写“这东西怎么运作”靠前者，写“我当时怎么判断错”靠后者。
- **数字密度不能裸读**：密度高不代表水，先看数字性质。参考博客都有 9–10 个/千字，但写的全是读者能
  拿去用的参数（字节数、握手次数、节点数）；自己的稿子如果同样是高密度却是“16 份/776 行/2 小时”，
  那是两种东西。规则见 `references/blog.md` 的数字一节。

## 7. 三十篇以后才稳：分桶与清洗

- **按语言分桶**：英文篇会同时拉高句均与 ASCII 占比。先按 `ascii_ratio > 50` 切出去，只对中文篇算句子与
  段落中位数，两个数都报，否则一个人的中文句长被英文长句带偏。
- **首尾段抽样要单独清洗**：站点级样板（页脚版权、书籍广告、系列目录、日期+tag 行）会让 30 篇的“结尾”
  全是同一句广告、“开头”全是 tag 串。用 `python3 scripts/first_last.py <dir> <prefix>` 取，不要手写切分。
- **先按空行切段，再逐段过滤**：顺序反过来（先把空行删掉再切）整篇会塌成一个段落，首尾抽样全错。
- **结构信号比指标更能定分型**：手册型作者常是“系列固定引言块开场（21/30）+ 结论前置 + 结尾放参考文献
  （27/30）”；随笔型作者是“无小标题（23/30）+ 长段承载 + 结尾抬一层”。先判他属于哪一型，再决定学他的
  结构还是只学他的句子——把随笔型的结尾搬到手册型的骨架上，会得到一段漂亮的空话。
